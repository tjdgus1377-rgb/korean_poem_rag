# 공유 제외 규칙과 clone 재현 — ISSUE #23

기준은 NF2003/NF2004와 `REPRO-005.md` R01~R03이다. 개인 자료를 제외하면서 추적 파일만으로 동일 초기 입력을 구성한다. 앱·코퍼스·매니페스트·기존 사용자 변경은 수정하지 않는다.

## 계약과 인수 조건

- IG01: `.env` 및 `.env.*`(빈 `.env.example` 예외), Streamlit secrets, 가상환경, `.sidam/`, `tmp/`, `data/cache/`, `data/derived/`, `evaluation/runs/`, SQLite/DB 및 journal/wal/shm, 개인 키 파일(`pem/key/p12`)을 기본 Git 추가 대상에서 제외한다. 무시 규칙은 이미 추적한 파일이나 과거 커밋에서 비밀을 지우는 기능이 아니다.
- IG02: `.env.example`, 코드·테스트·문서, `requirements.lock`, `sidam.toml`, 재현 매니페스트의 모든 입력과 공개 스냅샷·출처/권리, 최종 제출 문서는 무시하지 않는다. 원시 CSV/JSON/문서를 포괄 제외하거나 재현 입력 해시를 갱신하지 않는다.
- IG03: 프로젝트 `.gitignore`를 새 Git 저장소로 복사하여 전역 사용자 제외 파일·기존 추적 여부에 기대지 않고 경계 파일의 제외/허용을 검사한다. 빠진 제외 경로로 Red를 확인한 뒤 규칙만 보완하고 Green을 확인한다. `check_release.py`도 통과해야 한다.
- IG04: 커밋의 추적 파일을 새 디렉터리로 내보내 `.env`·로컬 DB·미추적 사용자 자료 없이 `verify_repro.py`가 동일 초기 입력을 확인해야 한다. 새 OS 설치·실제 GMS 초기 색인·AI 답변의 재검증은 이번 오프라인 검사의 범위가 아니며 기존 실검증과 구분한다.
- IG05: 재현 안내에 포함/제외와 본인 키·초기 DB 생성 절차를 명시한다. Windows/Linux CI와 독립 리뷰 후 머지한다.

## 검증과 한계

무시 경계 회귀, 기존 전체 테스트, 현재 추적 파일의 비밀/금지 경로 검사, 커밋 내보내기 재현 검사를 수행한다. API를 호출하거나 기존 앱 DB를 갱신하지 않는다. `.gitignore`는 임의 이름 문서 안의 비밀값이나 강제 `git add -f`를 차단하지 않으므로 배포 검사·리뷰를 함께 유지한다. Git 전체 과거 이력 정밀 검사를 이번 현재 파일 검사로 표현하지 않는다.
