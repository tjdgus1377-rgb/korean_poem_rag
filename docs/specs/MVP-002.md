# MVP 구현 계약 - ISSUE #2

- 기준: `docs/SPEC.md`, [ISSUE #2](https://github.com/tjdgus1377-rgb/korean_poem_rag/issues/2)
- 상태: 구현 착수, 완료 판정 전
- 실제 기준 PDF는 저장소의 `rag_pjt.pdf`이다. 현재 `prd.pdf`는 없다.
- API 연결 확인: 기존 GMS의 gpt-5.4-nano 채팅, text-embedding-3-small 임베딩(1536차원) 사용 가능 확인. 키는 기록하지 않는다.

## 구현 범위와 순서

데이터 어댑터 → 두 컬렉션 → 프롬프트·수집 → 그래프·검색 → Streamlit 화면을 같은 구현 브랜치에서 단계별 구현한다. 모든 단계의 인수 테스트를 코드보다 먼저 작성하고, 실패·통과 기록을 남긴다. 필수 요구사항·AC 매핑은 상위 SPEC을 따른다. 심화는 포함하지 않는다.

## 구체화

- 모듈은 `sidam/` 패키지에 둔다. 진입점은 `step7_skeleton.py`를 발전시킨다.
- 외부 본문의 이용 조건은 제공자별 명시 정책 또는 개별 승인 매니페스트로 검사한다. 권리 미확인 원문은 pending으로 분리한다. 기존 큐레이션 요약과 시 전문을 원출처의 원문 전문이라고 표시하지 않는다.
- 초기 주제 텍스트는 실제 확인한 interpretation 노트의 요약을 그대로 모아 설명으로 사용한다. 새 주제 태그를 자동 생성·검토 완료로 표시하지 않는다. 화면에는 ‘해설 기반 주제 설명’이라고 표시하고 note_id를 보존한다.
- 연도는 검토된 `data/curation/field_overrides.json`만 파생 필드에 반영한다. 원시 연도는 reported_year로 보존한다. 검증값 없는 작품은 최초 발표 미확인이다.
- 원문·해설 자격은 `data/curation/source_policy.json`과 출처별 기록을 사용한다. 명시 정책을 확인하지 못한 원출처의 본문을 자동 허용하지 않는다.
- 선택 작품 전문은 가능한 한 그대로 한 청크에 유지하고, 1000자보다 긴 경우 연·행 경계를 우선해 분할한다. 해설은 1000/200자로 시작한다.
- `VectorStore.sync_poems(records)`, `sync_source(doc)`, `retrieve(poem_id, question, quote)`가 색인과 검색 계약이다. 재색인 시 해당 출처의 잔여 청크만 제거하고 다른 작품·출처는 보존한다.
- 원격 임베딩을 쓰되, 단위/통합 테스트는 의존성 주입한 결정적 임베딩을 사용한다. 테스트 임베딩을 실서비스 의미 검색이라고 표시하지 않는다.
- API 준비 실패는 한국어 오류로 변환한다. 키/프롬프트/trace는 UI에 전달하지 않는다. 연결 스모크 외에 저장소의 .env 내용을 출력하지 않는다.
- P1/P2는 JSON 구조와 ID를 검증하고 1회 수정 요청한다. P1 외부 검색 실패는 작품 제목+시인 검색어로 대체할 수 있다. P2 실패 시 확인된 작품 자체 문서만 유지하며 임의 후보는 선택하지 않는다.
- query 캐시는 SQLite로 성공/empty/failed 상태를 저장한다. 실패를 성공 캐시로 쓰지 않는다. 정상 캐시는 반복 호출 때 외부 HTTP 요청이 없어야 한다.
- 기존 자료로 충분한 질문은 추가 수집을 생략한다. 근거가 맥락뿐이거나 질문의 핵심 표현이 없으면 추가 수집을 시도한다. 수집 결과 없음/장애는 표시한다.
- 기본 외부 수집은 한국어 위키백과 API 어댑터다. 연락처 식별·호출 간격·Retry-After를 지키고 허용된 호스트의 API만 호출한다.
- P3는 근거 번호를 검증한다. 무인용 또는 잘못된 번호는 한 번 수정 후에도 실패하면 검증 실패로 안내한다. 관련 자료가 없으면 모델 호출 없이 확인 불가로 응답한다.
- 작품별 대화는 브라우저 세션 안에서만 보존한다. 자동 스냅샷은 당시 근거를 복사해 저장한다.
- 키 없는 상태에서도 작품 목록·전문/출처·미확인 상태를 탐색할 수 있다. 유료 검색·생성·임베딩 작업만 비활성화한다. 이미 있는 색인은 키 누락 때문에 삭제하지 않는다.
- 초기 UI에 별도 색인 동작을 제공하고 시작 시 외부 임베딩을 자동 반복하지 않는다. 색인 fingerprint가 같은 경우 재임베딩하지 않는다.

## 검증 계획

pytest: 데이터 정합성·연도·주제 출처, 실제 Chroma 임시 DB의 멱등성·작품 격리·청킹, JSON 계약·인용, 모의 HTTP 수집 캐시·429·작품 문서 보존, LangGraph 두 노드·근거 없음, Streamlit AppTest 세션·오류 흐름.

CI: Python 3.12, 고정 requirements와 pytest 설치, 유료 API 없는 자동 테스트, 로그·결과 아티팩트. 실제 키로 수행하는 스모크와 브라우저 검증은 별도로 보고한다.

## 이번 구현의 완료 판단

테스트·실연결·CI·독립 리뷰 결과를 따로 기록한다. 모든 AC가 자동으로 충족되었다고 주장하지 않는다. 권리·최초 발표 연도·주제 검토 미확인 항목은 사용자에게 보이는 상태로 남기고 `data/derived/` 보고서에 집계한다.
