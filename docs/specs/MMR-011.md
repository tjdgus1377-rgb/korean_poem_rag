# 선택형 MMR 근거 검색 — ISSUE #11

PRD F2014(10·16쪽). 사용자는 MMR을 선택 옵션으로 추가하고 기존 similarity를 기본으로 유지하기로 결정했다. 작품 검색·메타데이터 색인·질문 생성 모델은 바꾸지 않는다.

## 동작

작품별 근거 검색에서만 `similarity`/`mmr`을 선택한다. 같은 poem_id 필터로 후보를 넉넉히 가져온다. 기본 설정은 fetch_k=20, lambda=.5, 기존 top_k=5. fetch_k는 top_k 이상, lambda는0~1의 유한 수여야 하며 잘못된 설정·모드를 거부한다. 설정은 sidam.toml과 재현 매니페스트에 기록한다. 임베딩 모델·차원은 섞지 않으며 재정렬은 저장된 벡터를 사용한다.

MMR은 query와의 코사인 관련성 lambda와 이미 선택된 청크와의 최대 유사도(1-lambda)를 조합한다. 첫 후보는 query 관련성 최대를 선택한다. 동점은 chunk_id로 안정 정렬한다. 0벡터의 코사인은0이다. 중복 ID는 한 번만 선택한다. 특정 출처의 유일성을 강제하거나 관련성이 낮은 출처를 무조건 넣지 않는다.

정확 작품 메타데이터는 첫 근거로 별도 포함한다. 선택 구절을 담은 원문 예약 청크는 두 방식 모두 보존한다. 예약 청크도 MMR의 중복성 기준에 포함하며 top_k 예산을 소비한다. 최종 근거의 모든 poem_id는 선택 작품이어야 한다. 기본 similarity의 기존 결과 선택 경로는 유지한다.

UI에서 검색 방식을 선택하고 답변에 당시 방식을 기록한다. 옵션을 바꿔도 과거 답변/출처/방식은 바꾸지 않는다. retrieve/generate 두 노드는 유지한다.

## 인수 조건·비교

AC-M1: 관련성이 높은 거의 중복 청크와 관련 있는 다른 청크를 둔 고정 벡터에서 MMR이 후자를 선택함을 확인한다. lambda=1,0·0벡터·동점·잘못된 설정도 검증한다.

AC-M2: 실제 임시 Chroma에서 두 방식의 작품 격리·정확 메타데이터·예약 원문·개수 제한을 검증한다. 기본값은 similarity다.

AC-M3: 같은 벤치마크 질문의 두 방식에 대해 source Recall@k/MRR·출처 수·선택 ID를 기록한다. 고유 출처 수 증가는 문학적 답변 품질 개선의 충분조건이 아니며 결과에 따라 장단점을 보고한다. 실제 브라우저에서 MMR 선택·질문·당시 방식/출처를 확인한다.
